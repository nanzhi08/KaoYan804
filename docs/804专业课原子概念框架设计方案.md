# 804 专业课原子概念框架设计方案

## 1. 目标与边界

本方案用于定义上海第二工业大学 804《数据结构与高级程序设计》专业课笔记的原子概念框架，服务对象是后续的 `C_MOC` 与 `DS_MOC` 两个入口文件。

本阶段只完成框架设计，不直接创建或修改 `二工大804资料包/考研专业课笔记` 下的 `C_MOC.md`、`DS_MOC.md` 及其原子笔记。

设计遵循以下原则：

1. 先按 804 出题方式组织顶层结构，再向下映射考纲与教材。
2. 概念粒度尽量细，后续单条笔记只解释一个稳定知识点。
3. 同一概念只保留一个主入口，避免在同一学科内部重复造点。
4. 主干严格服从 804 考纲，教材超纲内容默认不放入主干。

机器可读版本见 [804专业课原子概念框架.json](/C:/Users/zhangsihai/Desktop/考研知识库系统/docs/804专业课原子概念框架.json)。

## 2. 总体组织法

### 2.1 为什么不用“纯教材目录”

如果 `C_MOC` / `DS_MOC` 直接照教材目录展开，后续笔记会更像“章节摘要”，不利于按题型复习，也不利于把同一概念在选择、阅读、计算、编程中的不同考法串起来。

因此顶层采用“考法优先”，二级再回落到教材和考纲知识域：

1. 顶层回答“考试怎么考”。
2. 二级回答“这个考法主要调哪些知识域”。
3. 原子概念回答“这一题到底卡在哪个最小知识点上”。

### 2.2 原子概念表示

原子概念统一用 `[[概念名]]` 表示。当前只做命名和归类，不在笔记目录中落文件。

后续每个原子概念建议至少保留以下属性槽位：

- C 语言：教材出处、常见陷阱、典型题型、关联真题
- 数据结构：公式、复杂度、易错点、典型计算题、相关算法题

## 5. 框架组织规则

1. 同一概念只保留一个主入口，不在 `C_MOC` 或 `DS_MOC` 内部重复建点。
2. 一个概念即使同时承担“定义题”“计算题前置”“编程题前置”角色，也仍然只保留一个原子入口。
3. 顶层考法区负责组织“怎么看题”，知识域负责组织“题目考哪块”，原子概念负责组织“最小知识单元是什么”。
4. 后续如果落地为 Markdown，建议 `MOC -> 知识域 -> 原子概念` 三层均以链接组织，而不是复制内容。

2. 再让 `C_MOC` / `DS_MOC` 改为读取本方案中的“考法区 + 知识域 + 原子概念”结构。
3. 最后把题目映射从“章节”逐步升级到“章节 + 原子概念”双层映射。
