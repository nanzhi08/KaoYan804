# 学习复习闭环实现计划

## 目标

本系统的学习闭环以知识点为主轴，把刷题记录、知识点掌握度、复习计划、薄弱点队列和仪表盘目标连接起来。

核心闭环：

```text
选择知识点/章节/题型
  -> 抽题练习
  -> 提交答案并写入 practice_records
  -> 更新 knowledge_mastery
  -> 生成待复习知识点和薄弱点队列
  -> 回到仪表盘/学习统计继续定向刷题
```

## 数据来源

### practice_records

记录每次刷题提交：

- `question_id`
- `user_answer`
- `is_correct`
- `time_spent`
- `practice_mode`
- `created_at`

`created_at` 当前按 UTC 存储。今日统计使用“本地今日 0 点换算为 UTC 边界”查询，避免北京时间 0 点到 8 点之间今日刷题数被算成 0。

### knowledge_mastery

记录每个知识点的学习状态：

- `mastery_level`：0 到 1 的掌握度
- `ease_factor`：SM-2 难易系数
- `interval_days`：复习间隔
- `repetitions`：连续有效复习次数
- `total_attempts`
- `correct_attempts`
- `last_reviewed_at`
- `next_review_at`

`next_review_at = null` 视为尚未排程，当前应进入待复习队列。

## 刷题后如何更新掌握度

`POST /api/practice/submit` 完成三件事：

1. 按题型判分，得到 `is_correct` 和 `score_ratio`。
2. 写入 `practice_records`。
3. 找到题目关联的知识点，更新或创建对应的 `knowledge_mastery`。

刷题质量分：

- 答对：`quality = 5`
- 部分得分不低于 0.5：`quality = 3`
- 其他错误：`quality = 1`

掌握度采用滚动更新：

```text
new_mastery = old_mastery * 0.72 + practice_signal * 0.28
practice_signal = quality / 5
```

同时更新 SM-2 参数，给出下一次复习时间。

## 复习计划如何生成

`GET /api/review/due` 返回：

- `next_review_at = null` 的知识点
- `next_review_at <= now` 的知识点

这些知识点按未排程优先、到期时间优先排序，最多返回 20 个。

`POST /api/review/{mastery_id}/review?quality=0..5` 会按 SM-2 更新：

- 掌握度
- 连续复习次数
- 复习间隔
- 难易系数
- 下一次复习时间

## 今日刷题目标如何计算

仪表盘的“今日刷题目标”来自 `GET /api/progress/overview`。

字段含义：

- `today_attempts`：本地今日 0 点之后的刷题记录数。
- `due_review_count`：当前到期或尚未排程的知识点数。
- `weak_knowledge_count`：掌握度低于 40% 的知识点数。
- `daily_target`：今日建议刷题目标。

目标公式：

```text
daily_target = min(
  30,
  max(
    10,
    10 + min(10, due_review_count * 2) + min(10, ceil(weak_knowledge_count / 10))
  )
)
```

解释：

- 基础目标是 10 题。
- 每个到期复习知识点增加 2 题，上限 10 题。
- 每 10 个薄弱知识点增加 1 题，上限 10 题。
- 最终目标最高 30 题。

## 薄弱知识点如何进入刷题

学习统计页和仪表盘会展示掌握度较低的知识点。

点击“刷这个知识点”后，前端会跳转到 `/practice` 并携带：

```ts
{
  knowledgePoint: { id, part, chapter, name },
  knowledgePointIds: [id]
}
```

练习页调用：

```text
GET /api/questions/random?knowledge_point_ids=<id>
```

这样可以避免只按科目抽题，确保补弱动作真正落到对应知识点。
