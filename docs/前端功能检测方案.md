# 前端功能检测方案

本方案用于检查登录后前端是否出现批量报错、题目是否能正常显示、刷题流程是否可完成，并作为后续前端改动的回归清单。

## 1. 环境与工具确认

- 启动后端：`cd backend && python run.py`
- 启动前端：`cd frontend && npm run dev`
- 打开前端：`http://127.0.0.1:5173/`
- 检查浏览器控制台：无 `error`，无 Ant Design 兼容性 `warning`
- MCP 检查：运行 `claude mcp list`；若提示 Git Bash 或 `git.exe` 路径不可用，先修复 `.mcp.json` 中 Git 路径和 Claude Code 环境

## 2. 登录后首屏检测

目标：进入首页时只加载当前页面必要数据，不能让隐藏页面同时发起请求。

检查步骤：

1. 打开首页 `/`。
2. 在 Network 面板筛选 `/api/`。
3. 允许出现：
   - `/api/health`
   - `/api/progress/overview`
   - `/api/progress/detail`
4. 首次进入首页时不应出现：
   - `/api/practice/stats`
   - `/api/practice/history`
   - `/api/practice/wrong-questions`
   - `/api/knowledge-points`
   - `/api/documents`
   - `/api/ai/*`
   - `/api/review/*`
5. 页面应显示“今日学习指挥台”、刷题入口、复习计划入口和薄弱章节区域。

通过标准：首屏无批量 toast、无控制台错误，隐藏页面接口不会在未访问时请求。

## 3. 刷题功能检测

目标：题目可以抽取、显示、选择答案、提交，并展示判题结果和解析。

检查步骤：

1. 进入 `/practice`。
2. 确认显示“先做一组，再复盘错因”和练习配置。
3. 点击“开始刷题”。
4. 确认题干、题型、难度、选项或输入框正常显示。
5. 单选题选择一个选项后，“提交答案”按钮应变为可用。
6. 点击“提交答案”。
7. 确认页面显示：
   - 正确或错误状态
   - 正确答案
   - 解析
   - “复盘动作”
8. 有多题时，确认“下一题/上一题”切换后已选答案能保留。

通过标准：请求 `/api/questions/random` 和 `/api/practice/submit` 成功，结果区正常展示，答案状态不会在切题时丢失。

## 4. 空题组与异常检测

目标：接口正常但无题目时，用户能得到明确反馈；接口失败时不出现重复报错。

检查步骤：

1. 使用筛选条件制造空题组，或让 `/api/questions/random` 返回空数组。
2. 点击“开始刷题”。
3. 页面应提示“当前筛选条件下暂无题目，请调整题型、范围或难度”。
4. 让同一接口连续失败。
5. 3 秒内同一接口同一错误最多只显示一次 toast。

通过标准：空数据不静默失败，重复错误不会刷屏。

## 5. 错题、复习和统计检测

目标：访问具体页面时再加载对应数据，页面之间不会互相触发后台请求。

检查步骤：

1. 进入 `/wrong-records`，确认只在进入后请求错题历史和待复习错题。
2. 点击“复习错题”，确认能跳转到刷题页并带入错题组。
3. 进入 `/review-plan`，确认待复习知识点、评分说明和提交复习结果正常。
4. 进入 `/progress`，确认总览、薄弱点行动表和章节掌握度正常。
5. 进入 `/knowledge-map`、`/documents`、`/ai-tutor` 时，确认对应接口只在页面访问后请求。

通过标准：页面数据按需加载，切换页面后已访问页面状态保留，未访问页面不触发请求。

## 6. 自动化回归门禁

每次改动前端后至少执行：

```powershell
cd frontend
npm run lint
npm run build
```

建议增加 Playwright 烟测，覆盖：

- 首页首屏只请求当前页接口
- `/practice` 能抽题并显示题干
- 单选题能选择答案并提交
- 提交后显示结果、答案、解析和复盘动作
- 控制台 `error` 和 `warning` 数量为 0
